PostgreSQL. It is a port: essentially all of its provider source code is
derived from the Npgsql project, which is licensed under the PostgreSQL
License. That project is recorded below with its origin, the version ported
from, the copyright holders, the full text of its license, and the
modifications made during the port. A second entry records the design lineage
of the PgSqlMapper API, which contains no third-party code.

Modifications made during the port:
  * The root namespace Npgsql was renamed to CodeBrix.PostgresClient (and every
    namespace beneath it accordingly), and NpgsqlTypes was renamed to
    CodeBrix.PostgresClient.PgSqlTypes. Every ported file records its origin on
    its namespace line as "//was previously: <original namespace>;".
  * Every identifier containing "Npgsql" was renamed to use "PgSql" instead
    (NpgsqlConnection -> PgSqlConnection, NpgsqlDbType -> PgSqlDbType,
    INpgsqlNameTranslator -> IPgSqlNameTranslator, and so on), and the source
    files were renamed to match.
  * Runtime-visible names were renamed the same way: the ActivitySource and
    Meter ("PgSql"), the EventSources ("PgSql" and "PgSql.Sql"), the logger
    categories ("PgSql.Connection", "PgSql.Command", ...), the AppContext
    switches ("PgSql.EnableLegacyTimestampBehavior", ...), the tracing and
    metric attribute names ("db.pgsql.*", "db.client.*.pgsql.*"), the schema
    DataSourceProductName, and "Npgsql" in exception and log message text.
    URLs pointing at the upstream documentation were left unchanged.
  * The diagnostic IDs of the [Experimental] API gates (NPG9001, NPG9002,
    NPG9003) were NOT renamed: an ID is a public contract, written into
    consumers' NoWarn entries and suppressions.
  * Conditional-compilation branches for frameworks other than .NET 10 were
    resolved and removed; #if DEBUG blocks were kept.
  * Block-scoped namespaces were converted to file-scoped namespaces, and
    using directives were normalized into one sorted block.
  * Nullable reference type annotations were removed (every "?" on a reference
    type and every "!" null-forgiving operator), following the CodeBrix
    family convention; value-type nullables are unchanged.
  * All "#pragma warning" suppressions and the GlobalSuppressions.cs file were
    removed. XML documentation was written for every public member that
    upstream left undocumented.
  * Strong-name signing, the public-API analyzer and the dependency on
    Microsoft.Extensions.DependencyInjection.Abstractions (unused by the
    provider code) were dropped. The upstream InternalsVisibleTo entries were
    replaced by one for this repository's test project.
  * Members that were already [Obsolete] upstream and that the provider itself
    still used were removed: the PgSqlCidr type (use System.Net.IPNetwork for
    cidr), the PgSqlConnection.ProvidePasswordCallback,
    ProvideClientCertificatesCallback and UserCertificateValidationCallback
    properties with their delegate types (use the data source builder's
    password providers and SSL callbacks), and the TrustServerCertificate and
    InternalCommandTimeout connection-string keywords (both did nothing).
    The tests of those members were removed with them.
  * The ServerCompatibilityMode and LoadTableComposites connection-string
    keywords were kept but are no longer marked [Obsolete]: they are the only
    way to configure type loading from a plain connection string (for example
    for servers that cannot answer the type-loading catalog queries).
  * Log messages: every value a log message passes as a structured argument
    now also appears in the message text (for example "Completed keepalive
    (connector 12)"), and the connection string is no longer passed to the
    logger at all - upstream passed it, with the password removed, as an
    unreferenced structured argument on the connection open/close events.
  * The connection-string-builder source generator renders its template with
    the CodeBrix.Templating library instead of the template engine upstream
    uses. The generator is a build-time tool and is not shipped in the
    package.
  * The library's reflection-based additions (PgSqlMapper, below) are marked
    [RequiresUnreferencedCode] / [RequiresDynamicCode].
  * Tests: the NUnit test suite was converted to xUnit v3 and SilverAssertions.
    The OpenTelemetry-based tracing and metrics tests were rewritten to use the
    in-box System.Diagnostics ActivityListener and MeterListener. The test
    database is a throw-away PostgreSQL Docker container configured like the
    upstream CI server, and the test users were renamed from npgsql_tests* to
    pgsql_tests*.

2. Dapper (API design lineage only - no code incorporated)
================================================================================

Project:      Dapper
Source:       https://github.com/DapperLib/Dapper
Copyright:    Copyright (c) Sam Saffron, Marc Gravell, Nick Craver, and Dapper
              contributors / Stack Exchange, Inc.
License:      Apache License, Version 2.0

The object-mapping API of this repository (the PgSqlMapper extension methods:
Query / Query<T> / QueryFirst / QueryFirstOrDefault / QuerySingle /
QuerySingleOrDefault / Execute / ExecuteScalar / ExecuteReader /
QueryMultiple and their async forms, plus the grid-reader concept,
anonymous-object parameters, unreferenced-parameter filtering and IN-list
expansion) is modeled on the public API surface and observable behavior of
Dapper, by way of the same API in the sibling CodeBrix.Sqlite library. The
implementation in this repository was written fresh and PostgreSQL-specific
(reflection-based materialization against the PgSql types in this library)
rather than ported from Dapper's source, so no Dapper source file, and no
fragment of one, is included; this entry records the API-design lineage only,
and the code in this repository is licensed solely under the PostgreSQL
License.
